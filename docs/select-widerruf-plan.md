# 셀렉 추가 주문 — 철회 안내 · 주문 버튼 · 철회 버튼 계획서

작성 2026-09-18 · 상태: **승인 2026-09-18(결정 1~3 전부 권장안) · 구현·배포 @966 + 프런트** — 기록은 roadmap Done Recently · 선행 작업: `docs/widerruf-function-plan.md`(@963, 예약 흐름)
근거 조문은 2026-09-18 gesetze-im-internet.de 원문으로 확인. 변호사 자문이 아니다 — 법정 서식·조문을 그대로 옮기는 데까지가 범위다.

## 1. 지금 상태

- **흐름**: 셀렉 v2(`select.studio-mean.com`, 출력 재주문 세션 포함)에서 고객이 기본 제공분을 넘겨 **추가 보정**(장당 €10/€20, 볼륨 할인)과
  **추가 인화·액자·포토카드**를 고르고 4단계 「제출」 → 서버가 금액을 확정·저장(`submitPhotoSelection` / 수정은 `updatePhotoSelection`) →
  접수 메일 C4/C5(`_sendCustomerSelectReceipt`). 대금은 나중에(픽업 현장·우편 전 이체). 사업자 송장 예약이면 인보이스 자동 발행.
- **새 계약인가**: 기본 제공분(패키지 포함 보정·인화, 마케팅 보너스, 서비스컷) 선택은 원래 촬영 계약의 이행이라 대상이 아니다.
  **유료 추가분은 웹 화면으로 맺는 새 원격계약**이다 — 예약 약관이 "기본 포함분 외 추가 인화·상세 보정은 포함되지 않는다"고 적어 별도 합의가 필요하다.
- **빠진 것**
  1. 철회 안내도, "철회권 없음" 고지도 없다.
  2. **주문 버튼이 「제출 / Submit / Absenden」** — § 312j Abs. 3 BGB: 돈을 내야 하는 온라인 주문은 버튼이 "zahlungspflichtig bestellen" 또는 그만큼 분명한 문구여야 하고,
     **Abs. 4: 아니면 계약 자체가 성립하지 않는다**. 지금까지의 추가금은 고객이 자발적으로 내서 문제가 드러나지 않았을 뿐, 청구 근거가 약하다.
  3. 가격에 "부가세 포함" 표기가 없다 — PAngV § 6 Abs. 1: 원격판매는 필수. 우편 발송비 무료 문구는 있다(Nr. 2 충족).
  4. 셀렉 사이트에 「Vertrag widerrufen」이 없다(§ 356a — 계약을 맺은 화면에 있어야 한다).
- print 사이트 고객 주문 경로(`select-print-order`)는 **어느 화면도 호출하지 않는다** → 범위 밖(죽은 경로).

## 2. 품목별 판정

| 품목 | 성격 | 철회권 | 할 일 |
|---|---|---|---|
| 추가 보정(유료) | 서비스 — 고객 사진을 보정한 파일 제작 | **있음**, 14일 | 철회 안내 + **조기 이행 요청**(보정은 바로 착수하므로). 완성·전달하면 소멸, 도중 철회는 진행분 대가(§ 357a Abs. 2) |
| 추가 인화·액자·포토카드 | 고객이 고른 사진으로 만드는 맞춤 물건 | **없음** — § 312g Abs. 2 Nr. 1 | 주문 전 "철회권 없음" 고지(Art. 246a § 1 Abs. 3 Nr. 1 EGBGB) |
| 견적형 인화(대형·특수) | 값이 정해지지 않은 요청 → 견적을 메일로 수락할 때 성립 | 없음(Nr. 1) | 같은 고지. 버튼 규정은 개별 연락이라 적용 안 됨(§ 312j Abs. 5) |
| 기본 제공분·보너스·서비스컷 | 원 계약 이행 | — | 없음 |

**보정을 서비스로 본다.** "디지털 콘텐츠"로 보면 작업 시작만으로 철회권이 소멸할 수 있지만(§ 356 Abs. 6) 분류가 확실하지 않다.
서비스로 보는 쪽이 고객에게 더 유리해서 **틀려도 위험이 없고**, 예약 때 만든 문구(`WIDERRUF_TEXT_`)를 그대로 쓸 수 있다.
진행분 대가는 장당 가격이라 계산이 쉽다: **완성한 장수 × 단가**.

## 3. 사장님 결정 사항

1. **추가 보정 조기 이행 요청** — 유료 추가 보정이 있으면 **필수 체크**(권장). 대안: 체크하지 않으면 제출 14일 뒤에 보정 착수(대기 관리가 필요).
2. **예약 페이지 버튼도 같이 고치기**(권장) — 여권 외 예약의 「예약 제출 / Submit Booking / Buchung senden」도 같은 조문 대상이다(계약금·취소 규정의 근거가 흔들린다).
   → ko「결제 의무가 있는 예약하기」 / en「Book with obligation to pay」 / de「Zahlungspflichtig buchen」. 여권은 무료·무구속이라 그대로.
3. **철회 접수 처리** — 기존 `/widerruf/`를 재사용하고, 사장님 알림 메일에 '셀렉 추가 주문'임과 품목별 안내(보정 = 진행분 공제 가능 / 인화 = 철회권 없음)를 싣는다.
   추가금 정리는 기존 `select-clear-extras`(권장).

## 4. 구현 범위 (승인 후)

**(a) 셀렉 4단계(최종 확인)** — 버튼 바로 위, 합계 상자 근처(§ 312j Abs. 2 "주문 직전·눈에 띄게")
- 유료 추가 보정 > 0 → 필수 체크박스(보정용 조기 이행 요청 문장) + 「철회 안내 전문」 링크(`booking…/widerruf/`). '전체 선택' 같은 묶음 없음.
- 유료 인화·액자·포토카드 > 0 → "맞춤 제작품이라 철회권이 없습니다(§ 312g Abs. 2 Nr. 1 BGB)" 한 줄.
- 합계 옆 「부가세 포함 / inkl. MwSt.」, 가격 안내에도 같은 표기.
- **버튼**: 합계 > 0 이면 ko「결제 의무가 있는 주문하기」 / en「Order with obligation to pay」 / de「Zahlungspflichtig bestellen」. 0원 제출은 지금 문구 그대로. 수정 제출도 같은 규칙.
- 문구 출처: 서버 `WIDERRUF_TEXT_` 에 3줄(보정용 조기 이행 문장 · 인화 고지 · 버튼 문구)을 더하고 **셀렉 세션 응답에 실어 보낸다**.
  셀렉 사이트는 CSP(`script-src 'self'`) 때문에 예약 사이트의 `widerruf-text.js` 를 실을 수 없다 — 네 번째 사본 대신 서버가 정본. 예약 쪽 사본은 같은 리터럴이라 대조기(`check-widerruf.mjs`)가 그대로 지킨다.

**(b) 서버 기록** — 셀렉 시트 맨 뒤 새 열에 `조기이행요청 시각·문구 버전`. 유료 보정이 있는데 요청이 없으면(옛 화면 캐시 등) 막지 않고 관리자 접수 알림에 ⚠ — 예약과 같은 방식.

**(c) 접수 메일 C4/C5** — 유료 추가금이 있을 때만:
"이 메일로 추가 주문을 확정합니다"(계약 성립 시점을 문서로 고정) + 품목·금액(부가세 포함) +
추가 보정: 철회 안내 전문 + 서식 + 조기 이행 요청 인용 + 철회 버튼(`buildWiderrufMailHtml_` 재사용) / 인화: 철회권 없음 고지.
0원 제출 메일은 그대로.

**(d) 철회 버튼** — 셀렉 사이트 하단(Impressum·Datenschutz 옆) 「Vertrag widerrufen」 → `booking.studio-mean.com/widerruf/?ref=<예약 서명 ref>&what=select`
(세션 응답에 ref 를 더한다 — 예약행 없는 세션은 ref 없이). `/widerruf/` 는 계약 칸을 "셀렉 추가 주문 — 상품·촬영일"로 미리 채우고,
서버는 `what=select` 를 받아 사장님 알림에 품목별 안내를 한 줄 더한다.

**(e) 예약 페이지 버튼**(결정 2) — `booking.js` 버튼 문구 3개국어 + 여권 모드는 기존 문구 유지.

## 5. 범위 밖 / 남은 것

- **배포 전에 받은 추가 주문**: 버튼 문구 때문에 계약이 성립하지 않았을 수 있다 — 미수 추가금을 강하게 청구할 일이 생기면 변호사 확인. 이번엔 손대지 않는다.
- 굿샤인 판매(메일) · 견적 메일 수락 계약의 철회 안내 — 별건(예약 계획서 5장 그대로).
- print 사이트 `select-print-order` 경로 정리(죽은 코드).
