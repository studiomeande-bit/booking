## 0. 요청

예약 시스템에 **바로 상담 가능한** 협력업체 3곳을 연결한다.

| # | 업체 | 고객이 필요한 순간 |
|---|---|---|
| A | 메이크업 + 웨딩드레스 대여 (1곳) | 프리웨딩·본식 예약 직후 ("드레스는 포함인가요?") |
| B | 플로리스트 (1곳) | 프리웨딩 부케·부토니에, 돌상/가족파티 꽃장식 |
| C | 돌상·백일상·한복 대여 (1곳) | 백일·돌 촬영 예약 직후, 돌 추천 메일 받은 때 |

## 1. 원칙 (브랜드 규정 적용)

- **광고가 아니라 준비 안내다.** 성공 화면·메일의 기존 "준비 가이드" 톤 그대로 — 조용하고 담백하게, 목록형.
  제목은 "함께 준비하시면 좋은 곳" (EN *Recommended partners* / DE *Empfohlene Partner*). 내부 명칭만 "협력업체".
- **사진이 주인공** — 로고·배너 금지. 업체명 + 한 줄 설명 + 상담 버튼 1개. 텍스트만.
- **결정 전에는 안 보인다.** 예약을 결정한 뒤(성공 화면)와 다시 읽는 문서(메일)에만. 히어로·상품 선택 그리드·동의/결제 단계에는 넣지 않는다 — 의사결정 방해 + 법적 동의 화면에 외부 링크 섞지 않기.
- **스튜디오 기본 제공과 충돌 금지.** 돌상/백일상 기본 셋팅은 이미 무료(프로필 프로페셔널 이상). 업체 C는 "더 풍성한 돌상·한복이 필요하면"으로 위치시킨다. 무료 안내 문구는 그대로 둔다.
- 예약·결제는 각 업체와 직접. 한 줄 고지: "Studio mean은 소개만 드리며 각 업체의 계약·결제에 관여하지 않습니다."

## 4. 어떻게 — 데이터·표시·링크

### 4-1. 데이터는 한 곳 (시트 `협력업체`)
세 군데에 하드코딩하지 않는다. `상품설정` 시트가 상품의 진실원장인 것과 같은 패턴으로 **시트 1장**을 두고 `ensureSheets_` 기본 헤더로 만든다.

| 열 | 예 |
|---|---|
| id | `makeup_dress` |
| 분류 | 메이크업·드레스 / 플로리스트 / 돌상·한복 |
| 업체명 | (사장님 제공) |
| 한줄설명 KO / EN / DE | "프리웨딩 메이크업·드레스 대여, 한국어 상담" |
| 상담언어 | KO / KO·DE / KO·EN — 독일 고객에게 중요 |
| 지역 | Frankfurt 등 |
| **바로상담 링크** | 카카오톡 채널 채팅 / 인스타 DM(`ig.me/m/…`) / WhatsApp(`wa.me/49…`) / 문의폼 — **대화로 바로 이어지는 링크 1개** |
| 보조 링크 | 인스타·웹 (선택) |
| 적용그룹 | `wed,baby,dolp,consult_wedding…` (쉼표) |
| 노출위치 | `success,mail,dolmail,consult` |
| 순서 / 활성 | 1 / Y |
| 제휴조건 메모 | 내부용(할인·수수료 등) — 고객 노출 안 함 |

- 프론트는 이미 받는 `getInitDataCustomer()` 응답에 `partners` 배열로 실어 캐시(상품 카탈로그와 같은 경로). 메일은 서버에서 같은 시트를 읽는다.
- 어드민 카드는 **Phase 3**. 3행짜리 시트는 사장님이 직접 고치는 게 더 빠르다. 자주 바뀌면 그때 카드.

### 4-2. 표시 (성공 화면·메일 공통 블록)
```
함께 준비하시면 좋은 곳
────────────────────────────
○○ 메이크업 & 드레스      상담 언어 KO · Frankfurt
프리웨딩 메이크업과 드레스 대여.          [카카오톡으로 바로 상담 →]

○○ 플라워                  상담 언어 KO·DE · Mainz
부케·부토니에, 돌상 꽃장식.             [인스타그램 DM →]

Studio mean은 소개만 드리며 각 업체의 예약·결제에는 관여하지 않습니다.
```
- 버튼 라벨은 링크 종류에 따라 자동: 카카오톡 / Instagram DM / WhatsApp / 문의하기. 새 탭, `rel="noopener"`.
- 링크에 `?ref=studiomean` — 업체 링크가 쿼리를 허용할 때만(카톡 채팅·ig.me는 허용). 업체가 유입을 알 수 있게. 추적 목적이 아니라 "Studio mean 소개로 왔다"를 대신 말해 주는 역할.
- 성공 화면 클릭은 `site-analytics.js`에 `partner_click {id}` 이벤트 1개 — 어느 업체가 쓰이는지 정도만.

### 4-3. 표기 의무 (법무 전제 — 독일)
- 단순 소개(대가 없음)는 외부 링크로 충분. 개인정보는 전달되지 않는다(클릭만).
- **수수료·할인 등 대가가 있으면** 상업적 협력임을 표기해야 한다(UWG 광고 표시). 그 경우 제목을 "협력 파트너(Kooperation)"로, 고지 문구에 한 줄 추가. §6-②에 따라 분기.
- 업체 로고는 쓰지 않는다(허락 문제 + 브랜드 규정). 업체명 텍스트만.

## 5. 단계

| Phase | 내용 | 규모 |
|---|---|---|
| **1** | 시트 `협력업체` + 성공 화면 블록(①) + 확정/접수 메일 블록(②) — wed·아기생일·dolp 조건 | 반나절, 배포 1회 |
| 2 | 돌 추천 메일(③) + 상담 성공 화면(④) + 상품 상세 1줄(⑤) | 2~3시간 |
| 3 | 어드민 카드 · 클릭 집계 보기 · 리마인드(⑥, 요청 시) | 필요 시 |

Phase 1 검증: 프리웨딩 1건·돌 스튜디오 1건 합성 예약 → 성공 화면 블록·메일 블록 3개국어 확인 → booking-delete 로 정리(기존 릴리스 게이트 방식).

## 6. 사장님 확정 필요 (이 답이 있어야 Phase 1 시작)

1. **업체 3곳 정보**: 업체명 · 바로상담 링크(카톡 채널/인스타/WhatsApp 중 무엇) · 상담 언어 · 도시
2. **제휴 조건**: 할인·수수료 등 대가가 있는가 → 있으면 "협력 파트너" 표기로 감
3. **메이크업**을 프로필·스튜디오 일반 촬영에도 노출할지 (기본안: 웨딩만)
4. `?ref=studiomean` 붙여도 되는지(업체에 "스튜디오민 소개 고객" 안내를 해 두었는지)
5. 명칭 확정: "함께 준비하시면 좋은 곳" vs "협력업체 안내" vs "추천 파트너"
