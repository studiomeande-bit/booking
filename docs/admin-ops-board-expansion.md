# 오늘의 운영 보드 확장 (확인 우선순위 카드)

작성일: 2026-07-12 Europe/Berlin
대상: `appscript/AdminV2.html` (프론트 전용 — Code.gs 변경 없음)

## 배경

마스터플랜 "오늘의 운영 보드"는 사실 이미 대시보드 **확인 우선순위** 보드(opsQueueGrid + opsWorkflowBoard)로 존재했다.
다만 9개 큐 중 7개만 카드로 렌더되고, 몇 개 중요한 큐가 빠져 있었다. 이번 작업은 신규 화면이 아니라 **기존 보드 확장**.

## 변경 결과: 카드 7개 → 12개

| 카드 | 상태 | 판정 기준 |
|---|---|---|
| 워크인 접수 | 기존 | 워크인 신규 & 미연결 |
| 수동확인 | 기존 | manual_review_required |
| 입금확인 | 기존 | 계약금 필요 & 미입금 |
| **미입금 경고** | 신규 | 입금확인 대상 중 `depositWarnedAt` 존재 (7일 리마인드 발송됨 → 10일 자동취소 임박) |
| 오늘 촬영 | 기존 | |
| **내일 촬영** | 신규 표시 | 큐는 이미 계산되고 있었음 |
| 셀렉 발송 | 기존 | 촬영완료 & 셀렉 미발송 |
| 보정 작업 (구 최종 전달) | 재정의 | 셀렉 제출/작업대기/재수정 — **출력 대기 상태 제외** |
| **출력·발송 대기** | 신규 | selectStatus ∈ {보정본확인완료, 출력} (고객 승인 후 인화/전달 단계) |
| 재예약 | 기존 | 촬영연기 |
| **사업자 송장** | 신규 표시 | 큐는 이미 계산되고 있었음 |
| **문의·상담** | 신규 | 리드(신규/상담중/견적발송) + 상담(신규/상담예정/상담중/견적준비) |

- 보정 작업 ∩ 출력·발송 대기 = 공집합 (파이프라인 단계 분리, 중복 카운트 없음 — 테스트로 검증)
- 미입금 경고는 입금확인의 부분집합이라 `처리 대기` 합계에는 중복 포함하지 않고 요약 줄에 별도 표기
- 워크플로 보드 05 Delivery 레인에 출력·발송 대기 반영

## 카드 클릭 이동

- 미입금 경고 → 예약 탭 + `depositFilter='warning'` (기존 "5일 경과 경고" 필터 재사용)
- 출력·발송 대기 → 예약 탭 + `activeOpsFilter` 클라이언트 필터
- 문의·상담 → 문의 리드 탭 (개별 행: 리드→리드 탭, 상담→상담 탭)
- 리드/상담은 로그인 시 silent 로드되고, 로드 완료 시 `renderAdminOpsCenter()` 재호출로 카드 카운트 갱신

## 의도적으로 뺀 것: 미수금 카드

로컬 입금 필드 기반 미수금 판정은 과거에 오탐(false positive) 문제로 정리된 이력이 있음
(`docs/current-status.md` Receivables Logic Decision — Lexware openAmount 우선).
정확한 미수금은 회계 탭의 월마감 체크리스트(`getAccountingMonthCloseChecklistAdmin`)가 이미 제공하므로,
대시보드에 근사치 카드를 만들어 혼란을 더하지 않기로 함. 필요해지면 Lexware 상태 동기화 이후 서버 계산으로 추가.
