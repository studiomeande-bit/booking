# 셀렉 포함 인화 — 주문으로 만들어지지 않던 문제 (2026-08-07, @741)

## 증상

사장님 신고: **"셀렉 페이지에서 출력 요청 시 A4 1장만 넘어온다. 상품별로 다른데.
보정본은 출력 선택이 없어도 시그니처 10×15가 기본인데 적용이 안 된다."**

## 흐름

```
셀렉 v2  state.prints
  → 제출 payload prints[]
  → 셀렉시트 '추가인화'
  → getSelectDashboard extraPrintsData
  → 인화앱
```

인화앱이 받는 건 이 사슬의 끝이다. `state.prints` 에 없으면 인화앱에도 없다.

## 원인 — 쿼터가 '할인 근거'로만 쓰였다

### 1. 신규 세션은 빈 주문으로 시작

```js
state.prints = state.editMode ? buildDecoupledPrintsFromExisting(...) : [];
```

상품 포함 쿼터를 주문 행으로 옮기는 코드가 **아예 없었다**. 고객이 손으로 한 줄씩 추가해야만 생긴다.

### 2. 그래서 A4 1장

고객이 `[인화 추가]` 를 한 번 누르면 `addPrintRow()` 가 **남은 쿼터 중 첫 번째**를 기본값으로 넣는다.
스튜디오 Basic 쿼터는 `basic_a4×1 + basic_10x15×2` — 첫 번째가 A4다.
한 줄만 추가하고 제출하면 A4 1장만 가고 **나머지 10×15 2장은 흔적 없이 사라진다.**

### 3. '보정본 기본 10×15' 는 죽은 코드였다

프리셋 자체는 있다 — `getDefaultPrintTypeForRegularIndex()` 가 쿼터를 순서대로
`state.photos[].printType` 에 쓴다. 그런데 제출 페이로드가 그 필드를 버린다:

```js
// 보정 리스트는 출력 정보를 담지 않는다 (분리형)
photos: state.photos.map((photo) => ({ num, note, isBonus, isService, source }))
```

**v2 디커플드 전환의 잔해다.** 계속 계산해서 저장하지만 신규 세션에선 아무도 읽지 않는다
(수정 모드의 레거시 복원에서만 읽힌다). [[select-v2-decoupled-arch]] 가 경고한 "v1 기능이
v2 에 자동 이식 안 됨"의 또 다른 사례.

### 4. 서버도 안 채운다

`computeSelectDecoupledPrints_` 는 쿼터를 **주문한 인화의 값을 상쇄**하는 데만 쓴다.
주문하지 않은 포함 인화를 추가하지 않는다.

### 5. 출력 단계를 통째로 건너뛸 수 있었다

```js
function canProceedStep3() {
  return !state.prints.some((print) => !String(print.photoNum || '').trim());
}
```

빈 리스트는 이 검사를 통과한다 → 인화 0장으로 제출 가능 → **포함 인화 전부 소실.**

## 수정

### 미리 채우기 (`seedIncludedPrints`)

출력 단계 진입 시(`goStep(3)`) 쿼터를 주문 행으로 펼치고, **보정 리스트 순서대로 사진번호까지 배정**한다.
'보정본은 출력 선택이 없어도 기본 인화' 규칙을 여기서 실현한다.

고객은 이제 스튜디오 Basic 이면 **A4 1장 + 10×15 2장이 이미 들어있는 화면**을 본다.
바꾸고 싶으면 바꾸고, 원치 않으면 지운다.

**안 채우는 경우** (전부 테스트로 고정):

| 경우 | 이유 |
|---|---|
| 수정 모드 | 기존 제출분이 복원돼 있다 — 덮으면 고객이 지웠던 항목이 되살아난다 |
| 이미 행이 있음 | 고객 입력 우선 |
| MRT·디지털 전용 | 실물 산출이 없다 (`sessionHasIncludedDeliveryOutput()`) |
| 쿼터 없음 / 주문 SKU 아님 | 여권의 `passport_country` 는 PRINT_OPTIONS 에 없어 걸러진다 |
| 한 세션 2회차 | `printsSeeded` 플래그 — **고객이 지운 행이 되살아나지 않는다** |

보정본이 쿼터보다 적으면 남는 행은 **빈칸**으로 둔다(임의 배정 금지 — 고객이 고른다).

### 야외 Plus / Premium 쿼터 신설

사장님 확정: **Plus 10×15 ×7 · Premium 10×15 ×10**.
이전에는 양쪽 테이블 모두 빈 배열이라 '포함 인화 없음'으로 취급됐다.
프런트(`product-delivery.js`)·백엔드(`Code.gs`) 동시 반영.

## 현재 쿼터 (양쪽 일치 확인)

| 상품 | 포함 인화 |
|---|---|
| 프로필 Basic / Business / Professional | 10×15 ×1 / ×2 / ×3 |
| 스튜디오 Basic / Plus / Premium | A4 ×1 + 10×15 ×2 / ×4 / ×6 |
| 야외 Basic | 10×15 ×5 |
| **야외 Plus / Premium** | **10×15 ×7 / ×10** ← 신설 |
| 프리웨딩 Plus / Premium | A3 ×1 + A4 ×2 + 10×15 ×3 |
| 암트 결혼식 | 10×15 ×15 |

### 무료 컷도 10×15 포함 (@742)

사장님 확정: **서비스 컷 · 마케팅 동의 보너스 컷 모두 슬롯당 시그니처 10×15 인화 1장 포함**
(큰 사이즈를 고르면 차액만).

- **서비스 컷**은 €3 크레딧이 이미 있었다. 다만 고객이 인화를 *주문해야* 적용됐다 →
  이제 미리 채워지므로 자동으로 붙는다.
- **마케팅 보너스**는 크레딧이 아예 없어 **정가로 청구되고 있었다.** 서비스와 대칭으로 신설.

핵심 함정 3가지:

1. **서비스 슬롯은 `isBonus` 도 true** 다. 보너스 번호 맵에서 `isService` 를 빼지 않으면
   한 장이 크레딧을 두 번 받는다(€6 할인).
2. **동의 판정은 제출값 우선.** 제출 시점에 시트 `마케팅동의` 는 아직 갱신 전일 수 있어
   행 값을 믿으면 방금 동의한 고객이 크레딧을 못 받는다. 미동의면 `bonusNums` 를 비워 넘긴다.
3. **상품 쿼터는 일반 보정본에만 배정.** 무료 컷까지 섞으면 공짜 컷이 A4 쿼터를 삼켜
   일반 보정본이 밀린다(A4 €10 짜리가 €3 크레딧만 받아 €7 청구되는 사고).

| 세션 | 인화 |
|---|---|
| 스튜디오 Basic + 보너스 2 + 서비스 1 | A4 1 + 10×15 2(쿼터) + 10×15 3(무료 컷) = **6장 전부 €0** |
| 보너스 컷에 A4 선택 | €10 − €3 = **€7 차액** |
| 마케팅 미동의 | 보너스 행 안 생김 · 크레딧 0 |
| 보너스 상한 초과분 | 정가 |

## 검증

**로컬 64개** — 2개 스크립트

`scripts/check-select-included-prints.mjs` (49) — 채우기·쿼터 테이블

- 쿼터 테이블 **프런트 ↔ 백엔드 전 상품 일치** (어긋나면 화면과 청구가 갈라진다)
- **쿼터 id 가 전부 주문 가능한 SKU 인지** — PRINT_OPTIONS 에 없는 id 를 넣으면 화면에서
  조용히 사라지고 미리 채우기도 건너뛴다(여권이 실제로 그 케이스)
- 상품별 채우기 결과(구성·순서·사진번호 배정·부족분 빈칸)
- 무료 컷 행 생성(순서·미동의·번호 없는 슬롯·쿼터 없는 상품)
- 안 채워야 하는 5가지 경우

`scripts/check-select-free-cut-prints.mjs` (15) — **서버 계산을 실제로 실행**

클라이언트 표시는 참고용이고 서버가 최종 청구라, `computeSelectDecoupledPrints_` 를
Code.gs 원본 그대로 뽑아 돌린다(상품 쿼터 조회만 스텁).
보너스 무료 · 상한 초과 정가 · A4 차액 €7 · 미동의 0크레딧 · **이중 크레딧 없음** ·
쿼터와 병행 6장 전부 무료 · 쿼터 없는 상품도 무료 컷은 나감.

## 남은 것

- 고객이 채워진 행을 **지우면 포함 인화는 여전히 소실된다.** 의도적 삭제라 막지 않았지만,
  포함분 미사용 시 리뷰 화면에 경고를 띄우는 건 검토할 만하다.
- 서버측 백필(제출 시 미사용 쿼터 자동 추가)은 넣지 않았다. 넣으면 구버전 캐시·건너뛰기까지
  막히지만, 고객이 일부러 뺀 인화가 되살아나는 부작용이 있어 사장님 판단이 필요하다.

# 별점(찜) 영속화 (2026-08-10, @752)

별점=찜 모델 전환으로 별점이 **순수 로컬 상태**가 됐다 — 탭을 닫으면 찜 전체가 증발한다.
며칠에 걸쳐 고르는 고객(돌촬영)에게 치명적이라 서버 저장을 붙였다.

- 셀렉시트 `별점JSON` 컬럼 + 공개 라우트 `select-ratings-save` (인증 = sessionId 자체, 다른 셀렉 라우트와 동일)
- 클라이언트: 별점 변경 2초 디바운스 저장, 단계 이동·탭 숨김 시 즉시 플러시.
  실패는 조용히(다음 변경이 재시도) — 찜은 UX 보조 데이터라 사용자를 막지 않는다
- 세션 페이로드 `existingRatings` 로 복원 — 재진입·제출 후 수정 모두 전체 찜이 돌아온다
  (이전엔 보정 선택분만 5점 백필)
- 서버 정화: selectPhotoNumKey_ 정규화·1~5 정수만·2000장·40KB 상한. **전체 스냅샷 덮어쓰기**라
  찜 해제도 영속된다
- 프리뷰 모드는 저장 안 함(세션 없음)

라이브 왕복 검증(합성 세션, 검증 후 삭제): 오염 항목 정화(9점·빈키 제거) ·
확장자 정규화(IMG_0001.jpg→img_0001) · 저장→복원 일치 · 찜 해제 영속.
