## 1. 지금까지 만든 것

| 영역 | 상태 |
|---|---|
| 앱 | 네이티브 macOS(`swiftc`, Xcode 불요), 항상 위 표시, 날짜 이동(`‹ ›`·달력·오늘), 메뉴바 항목 |
| 인증 | CLI와 같은 로컬 키 파일 직접 읽기 — 붙여넣을 토큰 없음 |
| 목록 | 시각·고객·상품·장소·연락처·준비 칩·현장 수납·계약금 경고, 카드 전체 클릭 → 상세 |
| 상세 | 전체 페이지. 예정→실제 시각·지연·소요·종료예정·다음까지 여유, 결제, 요청사항 원문 |
| 당일 운영 | 촬영 시작/종료(시작 시 지연 자동 계산), `+5/+10분`, 초기화, 겹침 경고 |
| ERP 쓰기 | 잔금 수령(금액·결제수단 드롭다운·수령일) → `booking-confirm-balance` |
| 체감 속도 | 날짜별 캐시 · 앞뒤 하루 프리페치 · 낙관적 갱신 · 화면 비우지 않음 |
| 서버 | `today-board`(+15초 캐시), `booking-delay-set`, `booking-shoot-mark`, dayops(스크립트 속성 14일) |

**구조적 한계 2가지 (개선 불가 / 설계상 선택)**
- **GAS 왕복 5~6초** — 함수 내부는 0.5초. 나머지는 플랫폼 오버헤드(32k줄 로드 + 302 왕복)이고
  서버 캐시가 적중해도 같다. 그래서 체감은 클라이언트에서만 개선 가능하다.
- **앱은 이 맥 전용** — 로컬 키 파일을 읽기 때문. 다른 기기는 웹 대시보드(토큰) 경로가 따로 있다.

## 2. 관측된 구멍

근거 없는 아이디어는 넣지 않았다. 아래는 데이터·코드로 확인한 것만.

**A. 오늘 픽업(수령)이 보드에 없다**
픽업은 스튜디오에 **사람이 있어야 하는 일정**인데 보드가 촬영만 보여준다.
`select-handover-pending`(kind: noshow/unclaimed/toship/fresh)과 셀렉 시트의 픽업예약일시가 이미 있다.
촬영 사이에 픽업이 끼면 지금은 알 방법이 보드 밖에 있다.

**B. 촬영 준비 설문 답변이 보드에 없다**
`촬영준비설문` 시트(`PREP_HEADERS`: 예약장부행·답변JSON·**요약**·**참고링크**)에 이미 쌓인다.
분위기·레퍼런스는 **촬영 직전에 가장 필요한 정보**인데, 보드는 예약 요청사항 메모만 보여준다.
설문을 방금 만들어 놓고 정작 현장에서 못 보는 상태.

**C. 촬영 후 흐름이 끊긴다**
`촬영 종료`를 눌러도 다음 단계로 이어지지 않는다. 실제로는 종료 직후에
샘플 링크(`booking-sample-send`)나 셀렉 링크(`select-create`)를 보내게 된다 — 지금은 어드민/CLI로 따로.

**D. 여권 건 특수 흐름이 없다**
여권/비자는 물량 대부분이고 촬영 후 바로 전달로 끝난다(`pass-photos-send`).
보드에서 그 한 동작을 못 해서 굳이 어드민을 열어야 한다.

**E. 알림이 없다**
화면을 봐야만 안다. 다음 촬영 10분 전, 시작 시각, 예정 소요 초과 — 이 세 순간은 알림이 맞다.

**F. 실제 소요시간이 14일 뒤 버려진다** ⚠️ 가장 값진 지점
`촬영 시작/종료`로 **실측 소요**가 생기는데, dayops는 스크립트 속성이라 14일 후 자동 삭제된다.
이 값이 쌓이면 **상품별 소요시간을 실측으로 교정**할 수 있다 —
지금 예약 슬롯의 `여권 15분 / 스튜디오 Basic 30분` 같은 값이 추정인지 실측인지 모른다.
슬롯 정확도가 올라가면 겹침·지연이 구조적으로 줄어든다.
**결정이 늦으면 데이터가 없다** — 이건 나중에 소급이 불가능하다.

**G. 하루 마감 대조가 없다**
보드는 "현장 수납 예정 합계"를 보여주지만, 실제로 받은 것과 맞춰보지 않는다.
SumUp 15분 동기화가 이미 돌고 있으니 대조 지점이 있다.

**H. 키보드 조작이 없다** — 촬영 중에 마우스를 잡는 것보다 단축키가 빠르다.

**I. 다른 기기에서 못 본다** — 웹 대시보드가 있지만 기능이 뒤처지고 토큰이 필요하다.

## 3. 우선순위

### Phase 1 — 촬영일 즉효 ✅ **완료 (2026-08-27, @861)**
1. ✅ **B. 준비 설문** — 상세에 「촬영 준비 설문」 섹션(요약 + 참고 이미지 링크 클릭 열기 + 제출일시),
   목록 카드엔 "준비 설문 있음 · 참고 N장" 표시. 서버 `readPrepByBookingRow_`(같은 예약 재제출 시 최신 우선).
2. ✅ **A. 오늘 픽업** — 보드 하단에 「오늘 수령 N건」 섹션(시각·고객·상품·수령방식·완료여부),
   미완 건은 상단 경고에도 한 줄. 서버 `readPickupsForDate_`.
3. ✅ **E. 알림 3종** — 10분 전 / 시작 시각 / 예정 소요 초과. 헤더 `알림` 토글로 끌 수 있고,
   (행+종류+날짜) 키로 중복 발송을 막는다. **오늘이 아닌 날짜를 보고 있으면 보내지 않는다.**
4. ✅ **F(기록만) 앞당겨 실행** — 소급이 불가능해서 Phase 3 중 기록 부분만 먼저 넣었다.
   `촬영운영기록` 시트(append-only): 예정시각·예정소요·시작·종료·**실측소요**·지연.
   dayops 를 초기화해도 이 기록은 남는다. 리포트·슬롯 교정은 Phase 3 그대로.

### Phase 2 — 촬영 후 흐름 잇기 ✅ **완료 (2026-08-27, @864)**
4. ✅ **C/D 통합** — `촬영 종료`를 누르면 카드·상세에 **전달 버튼**이 나타난다.
   여권 계열이면 `여권 전달`(`pass-photos-send`), 그 외는 `샘플 발송`(`booking-sample-send`).
   **셀렉 링크는 제외**(사장님 지시 — 필요 없음).
   · 시트를 열면 **먼저 dryRun** 이 돌아 "받는 사람 · 폴더 · 사진 장수"를 보여주고,
     폴더를 열어 눈으로 확인할 수 있다. 확인 버튼을 눌러야 발송된다.
   · 여권 쪽엔 dryRun 이 없어서 **서버에 새로 만들었다**(원탭 UI에서 고객 메일이 나가면 안 된다).
   · 함께 보낼 한마디 입력(여권=note / 샘플=message).
   · 실패 메시지는 서버 진단을 그대로 보여준다(예: "샘플 폴더를 찾지 못했습니다 — 260829_김혜수_샘플
     형식인지 확인… 루트 하위 532개 스캔, 샘플 폴더 8개 — 일치 없음").

## 5. 유지해야 할 원칙 (다음 작업자용)

- **예약일시를 바꾸지 않는다.** 지연·시작·종료는 당일 운영 메모다. 예약일시를 건드리면
  캘린더·확정메일·변경안내가 딸려 나간다. 영구 일정 변경은 `booking-reschedule`.
- **쓰기는 낙관적으로.** GAS 5~6초를 사용자가 기다리면 안 된다. 로컬 먼저, 실패 시 되돌린다.
- **서버 응답의 키를 빼지 않는다.** Swift 디코딩은 키 하나가 없어도 전체가 실패한다
  (`nextName` 누락으로 보드 전체가 빈 사고). 클라이언트는 `decodeIfPresent` 로 방어돼 있지만
  서버도 항상 채워 보낸다.
- **결제수단은 드롭다운만.** 자유입력은 정산 대조를 깬다.
- **고객 메일은 명시 지시 시에만.** Phase 2의 발송 동작은 반드시 확인 단계를 둔다.
