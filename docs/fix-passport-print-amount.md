## 증상 (재현된 사실)

여권/비자 예약에 **인화옵션(€5, 일부 €3)**이 붙으면 그 금액이 예약행 `잔금` 컬럼에는 반영되는데 **`총결제액` 컬럼에는 반영되지 않는다.**
회계장부(accounting-ledger)는 매출(gross)을 **`총결제액`**에서 읽으므로, 실제 수납액보다 €3~5 **적게 매출을 기록**한다. net/MwSt는 gross에서 파생(gross/1.19)이라 매출 자체가 누락되면 부가세도 함께 누락된다.

전자흔적 없는 현금건은 특히 위험 — 2026-Q2 665 EUR 누락과 동일 패턴.

## 관련 코드 (조사 시작점)

- 컬럼 매핑: `appscript/Code.gs`의 `BOOKING_COL` — `총결제액` / `계약금` / `잔금`.
- 에이전트 매출 읽기: `_bookingRowToAgentObject_` (Code.gs ~11074) — `total:parseMoneyValue_(총결제액)`, `balance:잔금`. **매출은 총결제액에서 나옴을 확인.**
- 회계장부: accounting-ledger 핸들러가 gross=총결제액, net=gross/1.19, tax=gross−net로 파생.
- 여권/비자 인화옵션이 `잔금`에 더해지는 지점을 찾아라 — 예약 생성/수정 경로(booking-create-manual, 프런트 booking 폼의 여권 인화 체크박스 처리, 또는 여권 상품 가격계산 함수). `총결제액`을 갱신하지 않고 `잔금`만 갱신하는 코드가 원인.

## 요구 작업

### 1) 근본원인 픽스 (필수)
여권/비자 인화옵션 금액이 **`총결제액`과 `잔금` 양쪽에 일관되게** 반영되도록 수정한다. 원칙: `총결제액 = 상품가 + 옵션(인화 등)`, `잔금 = 총결제액 − 계약금입금액`. 신규 예약·기존 예약수정 모두에서 성립해야 한다.
- 회귀 방지: 여권/비자 + 인화옵션 예약 생성 → `총결제액`이 인화 포함액인지 검증하는 케이스 추가(가능한 범위에서).

### 2) 금액 정정 에이전트 액션 (필수) — `booking-set-amount`
소급 정정 및 향후 예외 대응용. erp-agent + Code.gs에 신규 액션 추가:
- 입력: `rowIndex`, `total`(새 총결제액), 선택 `reason`(감사메모), 선택 `recomputeBalance`(기본 true: 잔금 = total − 계약금입금액 재계산).
- 동작: `assertAdmin_(token)` 게이트, `총결제액` 갱신, 필요시 `잔금` 재계산, 예약 메모/감사로그에 `[금액정정 YYYY-MM-DD] 30→35 사유:… (agent)` 1줄 남김.
- 가드레일: 취소/환불 상태 예약은 차단(기존 상태변경 액션의 패턴 참고). MwSt/net은 저장하지 않고 회계장부가 gross에서 파생하게 둔다(현행 유지).
- erp-agent.mjs 헤더 주석의 action 목록에 추가.
- 사용 예: `node scripts/erp-agent.mjs booking-set-amount --json '{"rowIndex":218,"total":35,"reason":"여권 인화옵션 €5 누락분 반영"}'`
