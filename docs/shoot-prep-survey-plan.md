# 촬영 준비 설문(레퍼런스 무드보드) — 기획안

Updated: 2026-08-25 Europe/Berlin
Status: **Phase 1 구현·배포 완료 (2026-08-26, @852~@854). 이미지 카드용 사진 선별만 오너 대기**

## 1. 문제 — 지금은 레퍼런스가 "메일로 보내주세요"다

확정 메일이 상품마다 "레퍼런스 1~3장 환영 / 원하는 분위기를 알려주세요"라고 **부탁만** 한다.
- 회수율이 낮다: 고객 대부분이 안 보내고, 보내도 카톡·메일·DM 에 흩어진다.
- 구조가 없다: "화사하게요" 같은 모호어가 오면 촬영 당일 즉석에서 다시 물어야 한다.
- 기록이 안 남는다: 캘린더·예약행 어디에도 무드 정보가 정리돼 있지 않다.

**목표**: 예약 확정 후 고객이 5분 안에 끝내는 설문 한 페이지. 답이 구조화되어
캘린더 설명·촬영 전 브리핑에 자동으로 실린다. 사진 선택형이라 언어 장벽이 낮다(3개국어).

## 2. 어디에, 어떻게

- **전용 페이지**: 셀렉과 같은 패턴 — `booking.studio-mean.com/prep/?id=<토큰>`.
  예약행 기준 토큰(셀렉 세션ID 방식 재사용), 제출 전까지 수정 가능.
- **진입점**: ① 확정 메일의 "레퍼런스 보내주세요" 문단을 **[촬영 준비 설문 작성하기] 버튼으로 교체**
  ② D-7 리마인드 메일에 미작성 시 한 줄 재안내 ③ 어드민 예약 행에 작성여부 표시.
- **대상 상품**: `prof` / `stud` / `wed` (+`snap` 은 wed 문항의 축소판). 여권·기업은 제외
  (여권은 규격 촬영, 기업은 상담 파이프라인이 이미 있음).
- **엔진 재사용**: 상담 페이지의 동적 설문(TYPE_CONFIG: groups → choices) 구조를 그대로 가져오고,
  선택지에 **이미지 카드**를 붙이는 것만 추가한다.

## 3. 이미지 방식 — 결정 필요 (§7-①)

| 안 | 장점 | 단점 |
|---|---|---|
| **A. 자체 포트폴리오 (권장)** | 저작권·초상권 완전 안전(마케팅 동의분) · **"이 스튜디오에서 실제로 나오는 결과"라 기대치가 정확** · 브랜드 일관 | 무드 축마다 3~4장씩 골라내는 준비 작업 (약 30~40장) |
| B. 저작권 프리(Unsplash/Pexels) | 준비 빠름, 무드 다양 | 다른 조명·장비·인물이라 **기대치 불일치 위험**(고객이 고른 무드를 우리가 재현 못 하면 클레임 소지) · 인물 사진의 초상권은 플랫폼 약관 의존 · CI 원칙("스톡사진 느낌 금지")과 충돌 |
| C. 혼합 | A 부족한 축만 B로 보충 | 톤 이질감 |

권장: **A**. 무드 "선택지"가 곧 "우리가 보증하는 결과물 범위"가 되는 것이 이 기능의 본질.
B를 쓰면 도구는 빨리 생기지만 "이렇게는 안 나오는데요"의 씨앗이 된다.
이미지 준비는 마케팅 동의 확인된 촬영본에서 사장님이 최종 선별(목록은 Claude가 초안 가능).

## 5. 답변의 목적지 — 받는 것만큼 쓰는 게 중요

1. **시트**: `촬영준비설문` 1장 (예약행 링크·제출일시·답변JSON·요약문).
2. **캘린더 이벤트 설명**에 요약 자동 append — 촬영 당일 폰에서 바로 보임:
   `[준비설문] 용도 LinkedIn · 무드 클래식포멀 · 배경 그레이 · 표정 옅은미소 · 안경반사주의`
3. **아침 브리핑**: 다가오는 촬영 중 D-3 이내 미작성 건 표시(과도한 리마인드는 안 함).
4. **어드민 예약 행**: 작성여부 뱃지 + 답변 보기.

**구현 완료 (Phase 1~2 일부)**
- 시트 `촬영준비설문`, 공개 라우트 `prep-get`/`prep-submit`, 에이전트 `prep-status`
- 토큰은 예약행 ref 재사용 — @830 에서 상품·금액 변경에 안 깨지게 고쳐 둔 것
- **문항 정의는 프런트에만** 둔다(프런트가 id·라벨·요약을 함께 전송, 서버는 저장만) —
  서버에도 두면 3개국어 문구가 두 곳에서 갈라진다
- 확정메일(prof/stud/wed/snap)에 **[촬영 준비 설문 작성하기] 버튼** 3개국어 자동 삽입
- 제출 시 **캘린더 설명에 `[준비설문]` 요약 + `[참고링크]` 주입** — 기존 설명은 보존하고 그 블록만 교체
- 미입력 문항은 셀렉과 같은 방식으로 스크롤+강조

**행 재사용 방지**: 예약 삭제 시 준비설문 행도 함께 정리하고 뒤 행 참조를 당긴다
(`repairRefsAfterBookingRowDelete_`). 그 전 잔재까지 막도록 **읽을 때 고객명 대조 가드**를 둔다 —
행번호가 재사용돼도 남의 답변을 보여주지 않는다.

**문항 구성 (2026-08-26 최종)**
- **공통 head**: 촬영 계기(7칩+자유) — "왜 찍는가"는 무드보다 컷 구성·디렉션을 크게 바꾼다
- **핵심 필수**: 형용사 16개·최대 3개 + 자유입력 (prof 인상 / stud 사진 느낌 / wed 그날의 느낌)
- **공통 tail**: 인화·액자 계획(여백 확보에 직결), 결과물 필요 시점(보정 순서 배정)
- **조건부**: 아이 호칭 = stud 또는 촬영대상 kids·baby / 반려동물 = 예약에 `dog` 옵션(+€15) 선택 시
  → 서버가 `ageGroup`·`optionKeys` 를 내려주고 프런트 `when` 이 거른다
- **필수는 1~2개뿐** — 급하면 30초, 자세히 쓰면 5분. 전부 필수면 아무도 안 끝낸다
- `max` 상한 도달 시 **가장 먼저 고른 것을 밀어낸다** — 버튼이 죽으면 고장으로 읽힌다(셀렉 교훈)

**형용사 16개 근거**: 10개 미만이면 자기 느낌이 없어 자유입력으로 새고 데이터가 뭉개진다.
24개를 넘으면 훑기를 포기한다. 모바일에서 짧은 단어 칩이 4줄 안에 들어오는 지점이 16~18개.
3개 상한은 조합이 방향을 만드는 최소치 — 5개 이상이면 우선순위가 사라져 "다 좋아요"가 된다.

**의상 벌 수 문항은 제거**(사장님 — 안 물어봐도 됨).
