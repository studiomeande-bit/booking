# 회계 월마감 기록 + 마감 후 변동 감지 (2026-08-06, @737~738)

## 발견 경위

[[bank-data-gap-detection]] 의 월마감 판정 개선을 끝내고 7월이 `ready: true` 가 된 직후,
**그래서 마감은 어디에 기록되나** 를 확인하다 알았다 — 아무 데도 기록되지 않는다.

`getAccountingMonthCloseChecklistAdmin` 은 **읽기 전용**이다. 체크리스트를 돌려 "마감 가능"을 봐도
그 사실이 남지 않으므로:

1. **지난달을 실제로 마감했는지 아무도 모른다.** 브리핑의 분기 마감(ELSTER) 리마인더는 분기당 한 번뿐이라
   그 사이 달들은 챙기는 신호가 없다. 7월 은행 CSV 미임포트가 한 달 내내 안 잡힌 것과 같은 구조다.
2. **마감·신고 후 그 달 숫자가 바뀌어도 조용히 어긋난다.** 이건 가정이 아니라 **오늘 실제로 한 일**이다 —
   7/28·7/30 입금을 8/6 에 소급 기록해 7월 수입이 뒤늦게 움직였다. 신고가 끝난 뒤였다면
   제출 숫자와 장부가 말없이 달라졌을 것이다(UStVA 정정신고 사유).

## 구현

### 1. `회계마감` 시트 (기간당 1행)

`기간시작 · 기간종료 · 마감일시 · 수입총액 · 지출총액 · 손익 · 납부부가세 · 회계건수 · 수입건수 · 지출건수 · 경고수 · 강제마감 · 메모`

`ensureSheets_` 에는 넣지 않았다 — 계약서 시트와 같은 **지연 생성**(`ensureHeaderSheet_`) 패턴이라
매 요청의 시트 보장 비용이 늘지 않는다.

### 2. `recordAccountingMonthCloseAdmin` — 마감 확정

- 체크리스트를 **직접 돌려** blocker 가 남아 있으면 거부한다. `force:true` 로만 강행(강제마감 컬럼에 기록).
- `close_drift` 는 gate 에서 제외 — **재마감이 바로 그 drift 를 해소하는 정상 경로**이기 때문.
  (이걸 빼먹으면 한 번 어긋난 달은 영원히 force 없이는 못 닫힌다.)
- 같은 기간 재실행 시 **행 갱신**(멱등) — 최신 스냅샷이 정본.

### 3. 체크리스트에 `close_drift` 체크 추가

마감 기록이 **있는 기간에만** 붙는다(없으면 체크 개수도 그대로 → 미마감 기간 영향 0).
마감 당시 스냅샷과 현재를 대조해 다르면 `fail`.

```
2026-08-06 22:10 마감 이후 지출 €2012.18 → €2012.19 (+0.01) · 회계건수 51건 → 52건 (+1) …
— 신고를 마쳤다면 정정신고 대상입니다. 확인 후 다시 마감 기록해 주세요.
```

**돈은 정수 센트로 환산해 정확히 비교**한다. 처음엔 `Math.abs(delta)<=0.01` 허용오차를 썼는데,
라이브 검증에서 **딱 1센트 변동이 방향에 따라 잡히기도 안 잡히기도 했다**(지출 +0.01 은 놓치고
손익 -0.01 은 잡힘 — 부동소수 뺄셈이 0.010000000000218 / 0.009999999999763 로 갈린다).
센트 반올림 후 정수 비교면 서브센트 잡음은 반올림이 흡수하고 진짜 1센트 변동은 항상 잡힌다. (@738)

### 4. 아침 브리핑 — 지난달 미마감 리마인드

5~25일 창에서 **지난달 마감 기록이 없으면** 액션 라인 추가. 마감 시트만 읽어 판정하므로
장부 재계산 없음(비용 ~0). 1~4일은 정산이 덜 들어오고, 26일 이후는 분기 리마인더와 겹쳐서 뺐다.

### 5. 어드민 UI (AdminV2)

월마감 패널에 **마감 기록** 버튼 + 상태 줄. 기록이 있으면 초록 `✅ 마감 기록됨`,
숫자가 움직였으면 빨강 `⚠️ 마감 이후 숫자가 바뀌었습니다` + 항목별 변동 내역.
blocker 가 남아 있으면 백엔드가 거부하고 사유(체크 이름)를 그대로 띄운다.

### 6. 에이전트 액션 2종 (총 146개)

| action | 용도 |

| `accounting-month-close-record` ✏️ | 마감 확정 (`memo`·`force` 지원) |

## 검증

**로컬 25/25** (`scripts/check-month-close-record.mjs`) — 스냅샷 정규화·행 왕복·drift 대조.
시트가 날짜를 `Date` 로 재해석하는 케이스(계약서에서 실제로 터졌던 버그), 서브센트 잡음 무시,
1센트 양방향, 금액 동일·건수만 변동(취소+동액 신규) 포함.

**라이브 E2E** (@737 → @738):

| 단계 | 결과 |
|---|---|
| 마감 전 7월 체크리스트 | `closeRecord:null`, 체크 9개 (drift 체크 미부착) ✅ |
| **4월 마감 시도**(blocker 1건) | `마감 보류 — 필수 처리 1건: 결제대조 검토` 거부 ✅ |
| 7월 마감 기록 | row 2, `2026-08-06 22:10`, 스냅샷 저장 ✅ |
| 마감 후 체크리스트 | 체크 10개, `close_drift: ok`, **시트 왕복 후 스냅샷 완전 일치** ✅ |
| **drift 유발** — €0.01 테스트 지출 추가 | `fail`, 지출·손익·회계건수·지출건수 4항목 검출 ✅ |
| 테스트 지출 삭제 | 원상복구 — drift 0, `ready:true`, 지출 19건 ✅ |
| 재마감 | row 2 갱신(`reclosed:true`), 이력 1건 유지 ✅ |
| 브리핑 `monthCloseDue` | `null` (7월 마감됨) — **지난달 기간 계산이 정확히 07-01~07-31 로 떨어짐을 반증** ✅ |

시트 왕복 일치가 핵심 관문이었다 — 여기서 타입이 뭉개졌다면 **마감 직후부터 거짓 drift** 가 떴을 것이다.
